# Git Workflow

## Стратегия ветвления

Используем **GitHub Flow** с небольшими адаптациями:

```
main ─────────────────────────────────────────── (всегда стабилен, деплоится в prod)
  │
  ├─── feature/TASK-123-add-user-avatar ──── (короткоживущие ветки)
  │
  ├─── fix/TASK-456-login-error ──────────── (баг-фиксы)
  │
  └─── hotfix/critical-payment-bug ────────── (срочные фиксы в prod)
```

## Именование веток

```
<тип>/<номер-задачи>-<короткое-описание>

feature/TASK-123-user-avatar-upload
fix/TASK-456-login-redirect-loop
hotfix/payment-double-charge
chore/update-dependencies
docs/add-api-guidelines
```

| Префикс | Когда использовать |
|---------|-------------------|
| `feature/` | Новая функциональность |
| `fix/` | Исправление бага |
| `hotfix/` | Срочное исправление в production |
| `chore/` | Рутинные задачи (deps, конфиги) |
| `docs/` | Только документация |
| `refactor/` | Рефакторинг без изменения поведения |

## Commit-сообщения

Используем **Conventional Commits**:

```
<тип>(<scope>): <описание>

[опциональное тело]

[опциональный footer]
```

```bash
# Примеры
feat(auth): добавить OAuth2 через Google
fix(users): исправить N+1 запрос при получении профиля
chore(deps): обновить Go до 1.22
docs(api): добавить примеры для /users endpoint
refactor(payment): упростить логику расчёта комиссии

# С телом
feat(notifications): добавить push-уведомления

Используется Firebase Cloud Messaging.
Поддерживаются iOS и Android.

Closes TASK-789
```

| Тип | Описание |
|-----|----------|
| `feat` | Новая функциональность |
| `fix` | Исправление бага |
| `docs` | Изменения в документации |
| `style` | Форматирование, пробелы (без логики) |
| `refactor` | Рефакторинг без изменения поведения |
| `test` | Добавление/изменение тестов |
| `chore` | Build-процесс, зависимости |
| `perf` | Улучшение производительности |
| `ci` | Изменения в CI/CD |

<Callout type="info">
  Настройте `commitlint` — он автоматически проверяет формат коммитов в pre-commit хуке. Конфиг уже есть в репозитории.
</Callout>

## Процесс работы

```bash
# 1. Синхронизироваться с main
git checkout main
git pull origin main

# 2. Создать ветку
git checkout -b feature/TASK-123-user-avatar

# 3. Работать и коммитить
git add -p  # добавляем изменения частями, а не всё подряд
git commit -m "feat(users): добавить загрузку аватара"

# 4. Перед MR — rebase на актуальный main
git fetch origin
git rebase origin/main

# 5. Пушим и создаём MR
git push origin feature/TASK-123-user-avatar
```

## Правила

- **Не коммитьте прямо в `main`** — только через MR
- **Squash** мелкие «WIP» коммиты перед ревью
- **Не делайте merge commit** при обновлении ветки — используйте rebase
- **Ветка живёт не больше 2-3 дней** — разбивайте большие задачи на части
- **Удаляйте ветку** после мерджа (GitLab делает это автоматически)
