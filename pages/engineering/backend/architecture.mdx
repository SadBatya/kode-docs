# Архитектура

## Общая схема

```
                        ┌─────────────────┐
     Internet ─────────►│   API Gateway   │
                        └────────┬────────┘
                                 │ gRPC / internal REST
              ┌──────────────────┼──────────────────┐
              │                  │                  │
     ┌────────▼───────┐ ┌────────▼───────┐ ┌───────▼────────┐
     │  user-service  │ │  auth-service  │ │payment-service │
     └────────┬───────┘ └────────┬───────┘ └───────┬────────┘
              │                  │                  │
     ┌────────▼──────────────────▼──────────────────▼────────┐
     │                      PostgreSQL                        │
     └────────────────────────────────────────────────────────┘
              │
     ┌────────▼───────┐         ┌─────────────────────┐
     │     Redis      │         │  notification-svc   │
     │  (кэш/сессии) │         │  (Kafka consumer)   │
     └────────────────┘         └─────────────────────┘
```

## Принципы

- **Микросервисная архитектура** — каждый сервис деплоится независимо
- **API Gateway** — единая точка входа, авторизация на границе
- **gRPC** — для межсервисного взаимодействия (типизация + производительность)
- **Event-driven** — асинхронные события через Kafka для некритичных операций

## Хранилища данных

| Хранилище | Использование |
|-----------|---------------|
| PostgreSQL 15 | Основное хранилище, по одной схеме на сервис |
| Redis 7 | Кэш, сессии, rate limiting |
| Kafka | Асинхронные события (уведомления, аудит-лог) |
| S3 / MinIO | Файловое хранилище (аватары, документы) |

## Окружения

| Окружение | URL | Назначение |
|-----------|-----|-----------|
| `dev` | `api.dev.kode.internal` | Разработка, частые деплои |
| `staging` | `api.staging.kode.internal` | QA-тестирование |
| `production` | `api.kode.ru` | Прод |

<Callout type="warning">
  Прямой доступ к prod-базе данных запрещён. Для отладки используйте staging или дамп данных (без PII).
</Callout>

## Добавление нового сервиса

1. Создайте репозиторий по шаблону: `gitlab.com/your-org/service-template`
2. Добавьте сервис в `docker-compose.yml` монорепо
3. Создайте Helm chart в `infra/charts/`
4. Добавьте namespace в Kubernetes
5. Настройте CI/CD по аналогии с существующими сервисами
6. Добавьте сервис в таблицу выше и обновите архитектурную схему
