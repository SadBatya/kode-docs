# Онбординг

<Callout type="warning">
  Все доступы запрашиваются через IT-тикет. Шаблон тикета — в Confluence: **IT / Онбординг / Шаблон запроса доступов**.
</Callout>

## День 1

<Steps>
### Получить доступы

Попросите вашего менеджера создать IT-тикет с ролью и отделом. Вы получите:
- Корпоративная почта (`@kode.ru`)
- Slack workspace
- GitLab (группа `your-org`)
- Jira / Linear

### Настроить 2FA

Обязательно включите двухфакторную аутентификацию во всех системах. Без 2FA GitLab не даст пуш-доступ.

### Зайти в Slack

Подключитесь к каналам своего отдела и к `#general`, `#dev-general`, `#announcements`.

### Познакомиться с командой

Напишите короткий пост в `#introductions`: кто вы, откуда пришли, чем будете заниматься.
</Steps>

## Неделя 1

<Steps>
### Настроить окружение

Следуйте [гайду по настройке инструментов](/getting-started/tooling).

### Клонировать репозитории

```bash
git clone git@gitlab.com:your-org/backend.git
git clone git@gitlab.com:your-org/frontend.git
```

### Запустить проект локально

Инструкции для каждого проекта — в `README.md` в корне репозитория.

### Прочитать документацию отдела

Перейдите в раздел [Разработка](/engineering) и изучите документацию вашего отдела.
</Steps>

## Первый месяц

- Познакомьтесь с архитектурой системы — схемы в разделе [Backend / Архитектура](/engineering/backend/architecture)
- Разберитесь с процессом код-ревью: [Code Review](/processes/code-review)
- Сделайте несколько задач из беклога под наблюдением ментора
