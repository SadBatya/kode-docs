# Что такое Git и зачем он нужен

**Git** — это распределённая система контроля версий. Она отслеживает
изменения в коде, хранит всю историю правок и позволяет нескольким
разработчикам работать над одним проектом параллельно, не мешая друг другу.

<Callout type="info">
  Во всех командах разработки Kode используется **GitLab** — платформа для
  хостинга Git-репозиториев. В GitLab мы храним код проектов, открываем
  Merge Request на ревью и настраиваем CI/CD для сборки и деплоя.
</Callout>

Зачем это нам на проектах в Kode:

- **История изменений** — видно, кто, когда и зачем поменял конкретную
  строчку кода (`git log`, `git blame`).
- **Ветки под задачи** — каждая фича или фикс разрабатывается в отдельной
  ветке и не ломает `master`, пока не пройдёт ревью.
- **Совместная работа** — несколько человек могут работать над разными
  частями проекта одновременно и потом безопасно объединить изменения.
- **Ревью через Merge Request** — GitLab поверх Git даёт возможность
  проверить код коллеги перед тем, как он попадёт в общую ветку.
- **Откат ошибок** — если что-то пошло не так, всегда можно вернуться к
  рабочему состоянию (`git revert`, `git reset`).
- **CI/CD** — пуш и мерж в определённые ветки запускают автоматическую
  сборку, тесты и деплой. Обычно пайплайны настраивает **DevOps-инженер**,
  если он закреплён за проектом — если нет, за это может отвечать команда
  разработки.

<Callout type="warning">
  Прежде чем начинать работу над проектом и открывать первый MR,
  **обязательно уточни у тимлида**, как именно ведётся разработка на этом
  проекте: как называть ветки, как оформлять коммиты и какой флоу принят
  именно здесь.

  Мы придерживаемся лучших практик работы с Git, и почти на всех проектах
  настроен [Husky](https://typicode.github.io/husky/) для автоматических
  проверок перед коммитом. Но так как проектов много, среди них есть и
  старые, — конкретные правила могут немного отличаться от проекта к
  проекту.
</Callout>

## Основные команды

| Команда | Что делает |
| --- | --- |
| `git clone <url>` | Скачивает репозиторий с GitLab на локальную машину |
| `git status` | Показывает текущее состояние: изменённые, новые, застейдженные файлы |
| `git add <файл>` / `git add .` | Добавляет изменения в индекс (staging) перед коммитом |
| `git commit -m "сообщение"` | Сохраняет застейдженные изменения в историю с сообщением |
| `git push` | Отправляет локальные коммиты в удалённый репозиторий |
| `git pull` | Забирает изменения из удалённого репозитория и вливает в текущую ветку |
| `git fetch` | Скачивает изменения из удалённого репозитория, но не вливает их |
| `git branch` | Показывает список веток / создаёт новую (`git branch <имя>`) |
| `git checkout -b <имя>` / `git switch -c <имя>` | Создаёт новую ветку и сразу переключается на неё |
| `git checkout <ветка>` / `git switch <ветка>` | Переключается на другую существующую ветку |
| `git merge <ветка>` | Вливает изменения из указанной ветки в текущую |
| `git stash` | Временно откладывает незакоммиченные изменения, чтобы вернуться к ним позже |
| `git log` | Показывает историю коммитов |
| `git diff` | Показывает построчные отличия между изменениями |
| `git reset` | Отменяет коммиты/изменения (осторожно, может стереть историю) |
| `git revert <commit>` | Откатывает конкретный коммит новым коммитом, не удаляя историю |

<Callout type="warning">
  `git reset --hard` необратимо удаляет незакоммиченные изменения — перед тем
  как его использовать, лучше сделать `git stash` или уточнить у тимлида.
</Callout>
